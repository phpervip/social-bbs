内部中间件链（请求入站 → 响应出站）

① 前置过滤层
CORS 跨域 Request ID 注入 请求日志 (pino) 请求体大小限制

所有请求必经，记录 traceId 用于全链路追踪

② 鉴权 & 安全层
JWT 校验 Token 黑名单检查 IP 白名单 CORS Origin 校验

🔓 公开路由（/api/auth/login, /api/auth/register）跳过 JWT 校验
   但依然执行限流、IP 黑名单、CORS 安全校验
🔒 受保护路由从 Header 提取 JWT，校验签名 + 过期时间，注入 request.user
🚫 Token 黑名单（登出后失效）通过 Redis 校验，TTL 与 JWT 有效期保持一致，自动过期清理

③ 限流 & 治理层
速率限制 (Rate Limit) 并发控制 超时控制 (Timeout) 熔断 (Circuit Breaker)

⏱ 基于 Redis 滑动窗口：未登录 30r/min，已登录 100r/min，发布/上传 10r/min
🛑 各下游微服务拥有独立熔断策略，单一服务故障不影响其他业务路由
   连续 5 次失败触发熔断，30s 后半开恢复

④ 路由转发层
请求路由匹配 gRPC 协议转换 负载均衡 重试 (幂等请求)

Fastify 路由 → 转换为 protobuf → gRPC 调用下游
K8s Service DNS 做客户端负载均衡
🔁 重试仅对 GET 等幂等接口启用，POST 写入接口禁用自动重试，避免重复请求

⑤ 后置处理层
响应格式统一 错误码映射 Prometheus 指标

统一响应体 { code, message, data }，gRPC 错误码 → HTTP 状态码映射
