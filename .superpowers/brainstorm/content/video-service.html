内部三层架构

Handler 层 (gRPC 入口)
VideoServiceGrpc — InitUpload / UploadChunk / CompleteUpload / GetVideo / GetPlaybackURL / DeleteVideo / GetTranscodeStatus
校验分片序号、尺寸；协议转换，无业务逻辑
Service 层 (业务核心)
UploadService — 分片上传编排（Init → Chunk → Complete）
TranscodeService — 转码状态机（pending → processing → completed / failed）
PlaybackService — 播放地址签发 + 权限校验
ThumbnailService — 缩略图生成调度
➤ 生产 video:transcoded（转码结果事件）
➤ 消费 video:transcode-task（待转码指令，FFmpeg Worker）
Repository 层 (数据访问)
GORM / sqlx — MySQL 操作
go-redis — 上传会话、播放凭证、元数据缓存
AWS SDK (S3) — 分片对象、HLS 文件读写
事务边界：CompleteUpload 在本地事务内更新视频状态

外部依赖

gRPC ⟷ Gateway — 接收上传/播放/查询请求
Kafka ➤ video:transcoded（转码结果事件）
Kafka ⟵ video:transcode-task（待转码指令，FFmpeg Worker 消费）
MySQL ⟷ video_db（独立库）
Redis ⟷ 上传会话 / 播放凭证 / 元数据缓存
S3 ⟷ 原始视频 + HLS 分片 + 缩略图

⭐ 文件分片上传 & S3 存储流水线

1
InitUpload：前端携带文件名/大小/类型 → 获取 S3 Multipart Upload ID → 创建上传会话 upload:{upload_id}（Redis Hash 存分片清单）→ 返回 upload_id + 已上传分片列表（断点续传）。InitUpload 阶段增加分布式锁（upload:init:lock:{video_id}），防止同一视频并行发起多次上传任务
2
UploadChunk：前端按 5MB/片 上传 → 分片直接上传至 S3（UploadPart 携带 partNumber）→ Redis 记录已上传分片 → 返回 200 OK（支持并发分片上传）
3
CompleteUpload：校验分片完整性（对比 Redis 清单）→ 调用 S3 CompleteMultipartUpload 完成合并（业务服务不执行文件拼接，由 S3 内部完成，降低服务器 IO 压力）→ 正式前缀 raw/{video_id}.mp4 → 清理 tmp → 本地事务写 videos 表 → 生产 video:transcode-task
4
失败恢复 & 碎片清理：分片校验失败 → 返回缺失分片列表，前端只补传缺失片；超时未完成的分片（TTL 24h），由定时任务调用 AbortMultipartUpload 清理 S3 碎片文件

⭐ FFmpeg 异步转码（Kafka 任务队列）→ HLS 分片分发

1
转码 Worker 组：消费 video:transcode-task（待转码指令）→ 先获取分布式锁（video:transcode:lock:{id} SETNX）避免 Kafka 重复消费重复转码 → 从 S3 拉取原始文件到本地临时目录 → 状态置 processing
2
FFmpeg 多码率转码：720p / 480p / 360p 三档 → 输出 .m3u8 + .ts 分片（6s/片）
3
产物回传 S3：上传到 hls/{video_id}/{quality}/*.m3u8 + *.ts → 清理本地临时文件
4
缩略图生成：FFmpeg 抽帧 thumb/{video_id}.jpg（首帧 + 中间帧）→ 写入 S3
5
完成通知：更新状态 completed + HLS 地址 → 生产 video:transcoded（转码结果事件）→ Notification Service 推送「转码完成」给发布者；失败 → 状态 failed，有限次数自动重试（上限 3 次），多次失败标记失败状态，支持人工重试
6
HLS 分发：播放请求返回 .m3u8 主播放列表 URL → 浏览器 HLS.js 请求 .ts 分片 → 全部经 CDN 边缘缓存分发，Video Service 不直接承载视频流量

⭐ 播放权限 & 视频元数据缓存

1
权限模型：视频三种可见性 — public（公开）/ followers_only（仅粉丝）/ private（仅自己）。GetPlaybackURL 校验：JWT 用户身份 + 视频 visibility + 关注关系（gRPC 调 User Service）
2
播放凭证：权限通过 → 签发短期 签名播放 URL（时效签名 URL + Referer 限制，实现基础防盗链，S3 预签名 TTL 5min）→ Redis playback:{video_id}:{user_id} 记录已授权用户，权限缓存依靠 TTL 自动失效，无需手动清理
3
分片防盗链：.ts 分片经 CDN 鉴权头校验（Referer + 时间戳签名），未授权请求返回 403，防止 HLS URL 泄露后任意盗播
4
元数据缓存：video:meta:{id}（Hash：标题/封面/时长/码率列表/状态）TTL 30min · 转码完成后删除重建 · 列表页批量取 MGET/HMGET 减少回源

数据库表 (video_db)

videos
id PK · uploader_id IDX · title · description · visibility · status IDX · raw_key · hls_key · thumb_key · duration · created_at IDX
status: pending → processing → completed / failed
uploads
upload_id PK · video_id · chunk_size · total_chunks · received_chunks · status · created_at
📤 分片上传会话 · 断点续传依赖 · 与 Redis 清单配合
transcode_tasks
id PK · video_id FK→videos.id · quality · status IDX · retry_count · error_msg · created_at
🎞️ 转码任务记录 · 有限次数自动重试（上限 3 次）· 多次失败标记 failed 支持人工重试 · Kafka 任务与 DB 状态双记录

Redis 缓存策略

upload:{upload_id}HashTTL 24h
上传会话 · 分片清单（bitmap/chunk list）· 断点续传 · 超时由定时任务清理 S3 碎片
upload:init:lock:{video_id}SETNXTTL 1h
InitUpload 分布式锁 · 防止同一视频并行发起多次上传任务
video:meta:{id}HashTTL 30min
视频元数据缓存 · 转码完成后删除重建
playback:{video_id}:{user_id}StringTTL 5min
播放授权凭证 · 与签名 URL 生命周期一致
video:transcode:lock:{id}SETNXTTL 30min
转码任务去重锁 · 防止 Kafka 重复消费重复转码

S3 对象布局：

tmp/{upload_id}/part_{n} ← 上传临时分片（24h 清理）
raw/{video_id}.mp4 ← 原始文件（完成后可选生命周期沉降）
hls/{video_id}/{quality}/index.m3u8 + seg_{n}.ts ← HLS 分片（CDN 缓存）
thumb/{video_id}.jpg ← 缩略图
