🧩 Module Federation 微前端架构

Webpack 5 Module Federation — Shell(Host) + 3 个 Remote

应用拆分

🏠 Shell (Host) Webpack Host

基座应用，负责整体布局、路由分发、登录状态管理。加载 Remote 子应用的组件。

  • 全局布局（左侧导航栏 + 右侧内容区）
  • 路由分发：/login, /register → User Remote；/home, /trending → Feed Remote；/video → Video Remote
  • 极简「B」Logo — 纯 CSS 几何字标
  • 统一持久化 JWT Token，向外共享 API Client 实例
  • 全局 EventBus（发布订阅），同步登录状态给所有 Remote 子应用
  • Error Boundary 全局兜底 — 子应用加载异常/运行时错误故障隔离
  • Loading Skeleton 统一加载态

👤 User Remote Remote

用户相关功能子应用，独立部署。

  • 注册 / 登录页面
  • 个人主页（帖子列表、粉丝/关注数）
  • 编辑个人资料
  • 关注/取关操作

📰 Feed Remote Remote

Feed 流相关功能子应用，独立部署。

  • 主页时间线（关注者帖子流）
  • 发帖 / 删帖
  • 点赞 / 评论
  • 搜索帖子 + 用户

🎬 Video Remote Remote

视频相关功能子应用，独立部署。

  • 视频上传页面（分片上传）
  • 视频播放器（HLS.js）
  • 视频详情页
  • 视频转码状态展示

关键架构原则

🔐

鉴权：EventBus 替代 Context

Shell 统一持久化 JWT，向外共享 API Client 实例。通过全局 EventBus 发布 auth:login / auth:logout 事件同步登录状态给所有 Remote。规避 React Context 在 Module Federation 跨应用隔离的限制。

🚫

跨子应用通信：禁止直接依赖

Remote 子应用之间 禁止直接依赖、禁止直接调用。所有跨模块事件通信统一通过 Shell 提供的全局 EventBus（发布订阅模式）。保持子应用独立性和解耦。

🛡️

故障隔离：Error Boundary

Shell 基座全局捕获子应用加载异常、运行时错误。单个子应用崩溃不影响整体网站，其余 Remote 正常运作。实现故障隔离。

📡

统一网络层：共享 API Client

所有子应用复用 Shell 基座共享的 API Client 实例，统一处理 Token 注入、401 拦截刷新、接口异常拦截。子应用不单独新建网络请求实例。

Shell 向外共享

共享实例（所有 Remote 共用同一实例）：

API Client (Axios 封装) EventBus (发布订阅) Layout (Sidebar + Content) Loading Skeleton ErrorBoundary ⚠️ 不含 AuthContext

共享依赖（singleton 模式，避免重复加载）：

react react-dom react-router-dom axios @mui/material (可选)

EventBus 事件列表

auth:login
Shell → Remote：用户登录成功，携带 Token
auth:logout
Shell → Remote：用户登出
post:created
Feed Remote → Shell：新帖子发布，通知其他子应用
video:transcoded
Video Remote → Shell：视频转码完成
profile:updated
User Remote → Shell：个人资料更新
notification:new
Shell → Remote：新通知到达，各子应用更新角标

构建 & 部署

每个子应用独立构建、独立部署、独立版本号：

shell.example.com → user.example.com/remoteEntry.js feed.example.com/remoteEntry.js video.example.com/remoteEntry.js

Shell 在运行时动态加载 remoteEntry.js，子应用独立发布不影响其他模块
